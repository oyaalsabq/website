# دليل فصل لوحة التحكم ورفع الموقع على GitHub والربط مع Pages CMS
## شركة أويا السبق للشحن والنقل الدولي (Oya Al Sabaq)

هذا الدليل يوضح لك بالخطوات العملية البسيطة كيف يعمل نظام **Pages CMS** وكيفية رفع الموقع إلى **GitHub** ونشره مجاناً.

---

### أولاً: فهم المعمارية (كيف يعمل النظام؟)

1. **الموقع العام (Public Website):**
   - هو الموقع الذي يراه عملاؤك وزوارك، وهو موقع ثابت (Static Web App) فائق السرعة، خالي تماماً من أي أزرار تحكم أو شاشات تسجيل دخول تظهر للعامة.
2. **المستودع (GitHub Repository):**
   - هو المكان السحابي الذي يحفظ كود الموقع وملفات المحتوى في مجلد `content/` وملف الإعدادات `.pages.yml`.
3. **لوحة تحكم Pages CMS (الخارجية المستقلة):**
   - Pages CMS **ليس كوداً تبرمجه أو ترفعه على سيرفر**!
   - هو تطبيق ويب سحابي جاهز على الرابط: `https://pagescms.org`
   - عند تسجيل دخولك بحساب GitHub، يقرأ ملف `.pages.yml` ويفتح لك واجهة تحكم كاملة بالعربية لتعديل النصوص والخدمات والفروع والمشاريع.
   - عند ضغط "حفظ" داخل Pages CMS، يقوم تلقائياً بإنشاء Commit في GitHub، فتقوم الاستضافة بإعادة بناء الموقع ونشره خلال ثوانٍ.

---

### ثانياً: خطوات رفع الموقع على GitHub

#### 1. تحميل ملفات المشروع إلى جهازك
قم بتحميل ملفات المشروع كاملة من مساحة العمل الحالية وتأكد من وجود:
- مجلد `content/` (الملفات: `settings.json`, `home.json`, `services.json`, `projects.json`, `news.json`, `branches.json`, `seo.json`).
- ملف `.pages.yml` في المجلد الرئيسي (Root).
- مجلد `src/` وباقي ملفات التكوين (`package.json`, `vite.config.ts`, `index.html`).

#### 2. إنشاء مستودع جديد على GitHub
1. ادخل إلى حسابك على [GitHub.com](https://github.com).
2. اضغط على زر **New Repository**.
3. سمّ المستودع باسم رسمي (مثلاً: `oya-al-sabaq-website`).
4. اختر نوعه: **Public** أو **Private** (Pages CMS يدعم النوعين مجاناً).
5. اضغط **Create repository**.

#### 3. رفع الملفات بالأوامر (Terminal)
افتح موجه الأوامر في مجلد المشروع ونفّذ الأوامر التالية:

```bash
git init
git add .
git commit -m "الإصدار الأول للموقع الرسمي لشركة أويا السبق"
git branch -M main
git remote add origin https://github.com/اسم_حسابك/oya-al-sabaq-website.git
git push -u origin main
```

### ثالثاً: ربط لوحة التحكم Pages CMS (في دقيقة واحدة)

1. افتح موقع: **[https://pagescms.org](https://pagescms.org)**
2. اضغط على **"Get Started"** ثم **"Sign in with GitHub"** ومنح الصلاحية للمستودع.
3. اختر المستودع الخاص بك: `oya-al-sabaq-website`.
4. بمجرد اختياره، سيتعرف Pages CMS فوراً على ملف `.pages.yml` الموجود في المشروع.
5. ستفتح لك لوحة تحكم رسمية أنيقة مقسمة بالعربية:
   - **بيانات الشركة:** لتعديل الهواتف، الواتساب، المقر، البريد.
   - **الصفحة الرئيسية:** لتعديل العناوين وإخفاء/إظهار الأقسام.
   - **الخدمات:** لإضافة أو تعديل خدمات الشحن البحري والبري.
   - **المشاريع:** لإضافة عمليات شحن جديدة مع الصور والتواريخ.
   - **الفروع:** لإضافة وتعديل بيانات الفروع والخرائط.
   - **الأخبار:** لإضافة مستجدات وبيانات الشركة.

> **ملاحظة:** يمكنك إضافة زملائك في الإدارة كمحررين للمحتوى عبر منحهم صلاحية Collaborator على مستودع GitHub فقط!

---

### رابعاً: الاستضافة المجانية التلقائية (Cloudflare Pages)

نوصي باستخدام **Cloudflare Pages** لأنها مجانية 100% للأنشطة التجارية، فائقة السرعة، وتمنحك حماية وشهادة أمان SSL تلقائية:

1. ادخل إلى [Cloudflare Dashboard](https://dash.cloudflare.com) وأنشئ حساباً مجانياً.
2. اذهب إلى **Workers & Pages** -> **Create application** -> **Pages** -> **Connect to Git**.
3. اختر مستودع GitHub `oya-al-sabaq-website`.
4. اضبط إعدادات البناء (Build Settings):
   - **Framework preset:** `Vite`
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
5. اضغط **Save and Deploy**.
6. خلال 30 ثانية ستحصل على رابط مباشر لموقعك (مثل `oya-al-sabaq.pages.dev`).

#### ربط الدومين الخاص بالشركة (Custom Domain):
داخل لوحة Cloudflare Pages، اذهب إلى تبويب **Custom domains** وأضف اسم نطاقك (مثل: `oya-alsabaq.com`).

### خامساً: النشر على Netlify (حل مشكلة الصور وضمان ظهورها 100%)

#### سبب اختفاء الصور سابقاً على Netlify:
في تطبيقات Vite، عند النشر على خادم استضافة (مثل Netlify)، المجلد المنشور هو فقط `dist/`. عندما كانت مسارات الصور مكتوبة كـ `/src/assets/images/...` فإن المتصفح يبحث عنها في مجلد `src` الذي لا يتم نشره على السيرفر!
**ما تم إصلاحه الآن:**
1. تم نقل جميع الصور إلى مجلد `public/images/`، ومجلد `public` يقوم Vite بنسخه تلقائياً بالكامل إلى `dist/images/` أثناء عملية البناء (`npm run build`).
2. تم تحديث جميع مسارات الصور في ملفات البيانات لتكون `/images/...`.
3. تم إنشاء ملف `netlify.toml` وملف `public/_redirects` لضمان التوجيه وتفادي أي أخطاء 404.

#### الطريقة الأولى: النشر التلقائي عبر GitHub على Netlify (موصى بها)
1. سجل دخولك على [Netlify.com](https://app.netlify.com).
2. اضغط على **"Add new site"** -> **"Import an existing project"** -> **"GitHub"**.
3. اختر مستودعك الخاص بشركة أويا السبق (`oya-al-sabaq-website`).
4. سيتعرف Netlify تلقائياً على ملف `netlify.toml`:
   - **Build command:** `npm run build`
   - **Publish directory:** `dist`
5. اضغط **Deploy Site**.
6. سيتم بناء الموقع وستظهر جميع الصور (شاحنات، سفن، مستودعات، وشعار الشركة) بوضوح تام ودون أي نقص!

#### الطريقة الثانية: الرفع اليدوي بالسحب والإفلات (Netlify Drop)
إذا كنت ترفع ملفات الموقع يدوياً دون ربطه بـ GitHub:
⚠️ **تنبيه هام:** لا تسحب مجلد المشروع الرئيسي بالكامل!
بل نفذ أولاً في جهازك:
```bash
npm install
npm run build
```
ثم اسحب **مجلد `dist` الناتج فقط** وأفلته داخل Netlify Drop! لأن مجلد `dist` هو الموقع المترجم الجاهز المحتوي على الصور وصفحة `index.html`.

---

### ملخص الدورة التشغيلية بعد الإطلاق:
1. يدخل مدير الشركة إلى `pagescms.org`.
2. يعدل نصاً أو يضيف فرعاً جديداً ويضغط **Save**.
3. يتم إرسال التحديث إلى GitHub تلقائياً.
4. تستشعر Cloudflare Pages التعديل وتعيد نشر الموقع المحدث تلقائياً خلال نصف دقيقة.
5. يرى الزوار التحديث على الموقع مباشرة دون أي تدخل برمجي!
